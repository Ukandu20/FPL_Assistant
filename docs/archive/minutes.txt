Minutes Model (v1) — Technical Guide & Operator Manual

This is a practical, “how it works + how to use it” guide for your minutes predictor with starter-awareness, cameo decomposition, GK routing, and versioned artifacts. I’ll also call out known limitations (notably: no-DNP rows) and the highest-leverage follow-ups.

1) Problem framing

We want expected minutes for each player in a fixture pre-deadline, plus probability surfaces that matter for FPL:

Why is this important?

It is the core backbone for which the rest of the models lie. If the accurac

P(start): probability of starting.

P(60+): probability of playing 60+ minutes (minutes points cliff).

P(play>0) a.k.a. P(cameo) when benched, and the expected cameo minutes if they do come on.

Core output is:

pred_minutes (hybrid of start vs bench paths)

p_start, p60, p_cameo, p_play (= p_start + (1−p_start)*p_cameo)

exp_minutes_points = clamp(p_play + p60, 0, 2)

Diagnostics CSVs and metrics.json for quality control.

3) Features (causal / pre-deadline safe)

For each row (sorted by player, season, date, gw):

Minutes history:

min_lag1 (last appearance minutes)

min_ewm_hl2 (EWMA of minutes with halflife≈2; causal via lag)

Recency:

days_feat (capped or log1p days since last appearance)

long_gap14 (1 if gap >14d)

Starter history:

start_lag1 (1 if started last)

start_rate_hl3 (EWMA of starts with halflife≈3; causal)

start_streak, bench_streak (consecutive prior starts/benches)

Context:

pos_enc (GK/DEF/MID/FWD → 0/1/2/3)

team_rot3 (XI changes rolling window proxy; optional)

fdr (venue-aware difficulty if supplied)

All these are shifted / lagged so they don’t leak post-deadline info.

4) Model heads & what each does
4.1 Start gate: P(start | X, pos)

Per-position LightGBM classifiers (GK/DEF/MID/FWD) with a global fallback.

Optional monotonic constraints on safe features (e.g., more recent starts → higher P(start)).

Optional isotonic calibration (per-position + global fallback).

Blending: p = blend * p_pos + (1−blend) * p_global where both exist (flag --gate-blend, e.g. 0.3).

Why per-pos? Starting dynamics differ a lot across positions (esp. GK).

4.2 Benched cameo decomposition

If benched, minutes are modeled via two components:

Cameo probability: P(cameo | bench, X, pos) trained on bench rows:

Per-position classifiers (+global fallback), optional isotonic.

In your current data, no DNP → bench rows almost always have minutes > 0, so this head collapses to ~1.0. That’s an honest reflection of the label space.

Cameo minutes: a regression head predicting the minutes if they do come on. We also put per-position caps learned from training cameo distributions (e.g., 95th/98th percentile by position).

Combined bench path minutes:

μ_bench = P(cameo | bench, X, pos)  *  E[minutes | cameo, bench, X, pos]


(With no DNPs, P(cameo) ≈ 1.0, so μ_bench ≈ the cameo minutes head.)

4.3 Starter minutes: E[minutes | start, X]

Regressor trained on starter rows. Objective is L2 (least squares).

Optional taper: shrink predicted starter minutes when p_start is low, to avoid over-confident 80–90’ when the start is doubtful.

4.4 60-minute cliff head: P(60+ | X)

Two modes:

Direct (--p60-mode direct): binary classifier using all rows (empirically your best so far: AUC ≈ 0.83–0.85).

Structured (P(60+) = P(start) * P(60+ | start) with per-pos models). Useful when the start gate is very strong.

Optional isotonic calibration improves Brier and interpretability.

5) Hybrid routing (core minutes prediction)

We compute three quantities:

Starter prediction: μ_start = E[minutes | start, X] (after taper if enabled)

Bench prediction: μ_bench (cameo probability × cameo minutes, capped per pos)

Soft mix: μ_mix = p_start * μ_start + (1 - p_start) * μ_bench

Then apply per-position thresholds (t_lo, t_hi):

If p_start ≤ t_lo(pos): use bench minutes (hard route).

If p_start ≥ t_hi(pos): use start minutes (hard route).

Otherwise: use the soft mix.

GK no-mix mode (--no-mix-gk): if GK and p_start > t_lo, route hard to starter minutes (reflects “GK either starts 90’ or doesn’t play” reality).

Finally, guardrails:

Clip very low p_start cases to max 10 or 30 minutes (configurable caps).

Clip final to [0, 120].

Typical run (what you just used)
py -m scripts.models.minutes_model_builder \
  --seasons 2020-2021,2021-2022,2022-2023,2023-2024,2024-2025 \

  --pos-thresholds "GK:0.15,0.55;DEF:0.25,0.70;MID:0.25,0.70;FWD:0.25,0.70" \
  --no-mix-gk

Key flags (what to tweak)

Calibration: --use-calibration, --use-p60-calibration

Routing: --pos-thresholds "GK:lo,hi;DEF:lo,hi;...", --no-mix-gk

Taper: --use-taper (shrinks μ_start when p_start is low)

Caps: --use-pos-bench-caps (data-driven 95–98th pct per pos cameo caps)

Blending: --gate-blend α (0..1) between per-pos start gate and global

P60: --p60-mode direct|structured

8) Versioning model artifacts

Latest: Every run updates <model-out>/latest (the working copy).

Versioned: If the versions directory has no version, first run creates versions/v1.
Subsequent runs keep writing to latest.
When you want to lock a new version, pass a version tag (e.g., --version-tag v2) or run your “bump” task—this will snapshot the current latest into versions/vX.

metrics.json includes code_version (e.g., 1.1.0) for traceability.

Recommendation: Treat versions/vX as immutable snapshots; iterate on latest. When satisfied, snapshot to vX+1.

10) Limitations & roadmap (blunt honesty)

No DNPs: Can’t model/validate bench no-shows right now.
Fix later: outer-join squad availability → create zero-minute rows.

Single-mode cameo minutes: Captures central tendency (10–25’) but not the long cameo tail.
Upgrade: two-mode cameo (short vs long) or quantile regression.

Threshold autotune: Currently tuned with the bench head in place, but you can weight bench error more heavily when you care about it (already supported internally).

P60 per-pos calibration: You can squeeze more Brier and reduce false “risky starters” with per-pos isotonic on the direct P60 head.

12) Failure modes & fixes

“UndefinedMetricWarning: AUC”
Means validation tail has a single class. The code already widens the tail window; otherwise AUC is omitted for that head. Safe to ignore; check Brier or rows count.

Bench minutes under-/over-clipped
Tweak per-pos cap percentiles (95 → 98 for DEF/MID); keep GK tight.

Overconfident starts around 0.6–0.8
Increase t_hi in --pos-thresholds or use stronger per-pos isotonic (keep --use-calibration on).

13) How to extend (when you’re ready)

Add DNPs into the training/test frames (outer join vs. fixture roster).

Two-mode cameo minutes: add P(long ≥30 | bench, X, pos) + two regressors μ_short, μ_long.

Per-pos isotonic for P60 (direct mode).

Autotune thresholds with a custom objective that weights bench MAE more when you’re focused on bench pain weeks.

14) Pushback (so you keep improving)

You’re relying on central cameo minutes. That’s safe but hides long-tail variance that bites DEF/MID benches. Make a note to implement the two-mode cameo once you can validate it.

Without DNPs, p_cameo is necessarily near 1. Don’t over-interpret its calibration; it’s a placeholder until you expand the dataset.

Don’t chase overall MAE too hard—optimize the EV minutes-points metric when making FPL decisions. You’re already in a good band there.

15) Example: reading the outputs downstream

Use pred_minutes to weight downstream xGI/xCS contributions (minute-scaled), not just binary ≥60.

For start-risk comms, prefer p60 and risk_start_sub60 = max(0, p_start − p60) to flag “likely starter but sub-60 danger”.
